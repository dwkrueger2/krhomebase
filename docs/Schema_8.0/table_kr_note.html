kr_note

Durable internal note attached to a matter, client, individual, entity, task, event, or other owner. Use it instead of burying note text in unrelated tables.

Common usage notes
  • Rows are retired rather than deleted: filter on archived_at (and is_active where present) in normal list views.
  • Controlled values are enforced by CHECK constraints on: owner_type, body_format, visibility. Update the constraint (table rebuild in SQLite/D1) when adding a value.
  • owner_type + owner_id form a polymorphic owner reference; the database cannot enforce it with a foreign key, so the API must validate it.
Raw SQL
CREATE TABLE kr_note (
  id TEXT PRIMARY KEY,
  owner_type TEXT NOT NULL CHECK (owner_type IN ('client','matter','individual','entity','document','asset','invoice','public_inquiry','general')),
  owner_id TEXT NOT NULL,
  note_type TEXT NOT NULL DEFAULT 'general',
  subject TEXT,
  body TEXT NOT NULL,
  body_format TEXT NOT NULL DEFAULT 'plain' CHECK (body_format IN ('plain','markdown','html')),
  visibility TEXT NOT NULL DEFAULT 'internal' CHECK (visibility IN ('internal','client_visible','private','system')),
  is_pinned INTEGER NOT NULL DEFAULT 0 CHECK (is_pinned IN (0,1)),
  is_confidential INTEGER NOT NULL DEFAULT 0 CHECK (is_confidential IN (0,1)),
  created_by_user_id TEXT,
  updated_by_user_id TEXT,
  created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  archived_at TEXT,
  FOREIGN KEY (created_by_user_id) REFERENCES user(id) ON DELETE SET NULL,
  FOREIGN KEY (updated_by_user_id) REFERENCES user(id) ON DELETE SET NULL
);
