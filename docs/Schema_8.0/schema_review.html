Findings & Recommendations

Observations from rebuilding the documentation from the live schema. Each item is a fact read from the database plus a suggested follow-up. Nothing here has been changed in the database.

1. Items that need a decision
  • Legacy source-system default. 3 tables (external_source_map, import_batch, matter_balance_snapshot) declare a DEFAULT for source_system naming the external practice-management system the data was first imported from. The Schema 8.0 documentation text avoids vendor names, but the raw SQL blocks show the default exactly as stored. If the project’s restricted-term policy covers that name, changing the default needs a D1 write (a table rebuild, because SQLite cannot alter a default in place); Claude will provide that command rather than run it.
  • Duplicate or overlapping structures. matter_activity_log and workstream_activity both record dated activity; entity.entity_subtype_legacy and entity.entity_subtype hold the same values; user.role_set_id and user_role_set both assign role sets; user.is_active and user.account_status both describe account state. Decide which is authoritative and retire the other.
  • Archive and diagnostic tables. client_lead_profile_legacy_orphan (reconciliation archive) and kr_crud_worker_smoke_test (worker smoke test) hold no business data and could be dropped from production once no longer needed.
  • Source database. This documentation was read from the development database krhomebase_dev. The DevSupport notes describe it as a refresh of the live database plus pending developer migrations, so confirm the live database matches before treating 8.0 as the production definition.
2. Data-model observations
  • Money is stored as REAL. 72 REAL columns exist, most of them amounts, rates, and balances. Floating point can drift in sums. Recommendation: for new money columns use integer cents; for existing ones, round at the API boundary and avoid comparing sums with equality.
  • Relationships not enforced by the database. 11 columns look like references (ending in _id) but have no FOREIGN KEY (listed below), plus the polymorphic owner_type/owner_id pairs. This may be deliberate (cross-database or optional references) but each one relies on the API for integrity.
  • Foreign-key delete behavior is mixed. Declared foreign keys use: 242 none declared, 54 SET NULL, 27 CASCADE, 2 RESTRICT. Most older tables declare no ON DELETE action, which means NO ACTION: deletes of a referenced row fail while children exist.
  • Timestamp defaults are mixed. created_at/updated_at defaults: 78 datetime(now), 41 strftime ISO-8601. Both are text; the strftime form is ISO-8601 with a T and Z, the datetime(’now’) form uses a space and no zone. Sorting works within one style but mixing them in one query can surprise.
  • Columns appended after constraints. Several tables (for example employee_time_card, employee_time_punch, payment_request) show later-added columns after their constraints in the stored DDL, a sign they were added with ALTER TABLE. Recreating the database from schema_d1_v8_0.sql is still correct; the column order simply reflects history.
  • Tables without created_at: action_review_stamp, asset_detail_bank, asset_detail_digital, asset_detail_entity, asset_detail_insurance, asset_detail_real_estate, asset_detail_retirement, asset_detail_tangible, asset_detail_vehicle, asset_ownership, asset_valuation, beneficiary_designation, content_sequence, entity_dba, entity_registration, kr_maintenance_gate, ledger_audit_log, matter_access, matter_party, matter_stage_history, risk_flag, task_assignee.

5. Documentation improvements made in 8.0
  • Rebuilt from the database itself instead of the prior HTML set; counts and DDL match the live schema exactly.
  • Removed external dependencies: Schema 7.0 pages loaded fonts and a diagram library from the internet, which broke offline use. 8.0 uses only local files.
  • Replaced placeholder text (for example “Content Asset table. Stores the operational fields...”) and generic column text with specific descriptions; allowed values are shown as chips from the CHECK constraints.
  • Corrected copy-and-paste errors from 7.0 (for example a matter-access column described as a session timestamp).
  • Each table page now has inbound and outbound relationships, inferred relationships labeled as such, constraints in plain language, index purposes, usage notes, a relationship map, and prev/next navigation.
  • Added canonical DDL (schema_d1_v8_0.sql), Mermaid source per domain, a changes-since-7.0 page, and this review.
