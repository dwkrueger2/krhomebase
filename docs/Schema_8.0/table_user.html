Table definition · Users, Roles, Permissions, Sessions, and Audit

user

A login account attached to an individual: sign-in email, password hash (when used), default role, role set, account status, profile image, and last login.

Common usage notes
  • is_active hides retired rows from pickers while keeping history; filter on it in active lists.
  • Controlled values are enforced by CHECK constraints on: role, account_status. Update the constraint (table rebuild in SQLite/D1) when adding a value.
  • Sensitive columns: password_hash. Never log them or return them to browsers.
Raw SQL
CREATE TABLE user (
    id                      TEXT PRIMARY KEY,
    individual_id           TEXT,
    email                   TEXT NOT NULL UNIQUE,
    password_hash           TEXT NOT NULL,
    role                    TEXT NOT NULL DEFAULT 'staff'
                                CHECK (role IN (
                                    'super_admin','attorney','paralegal','staff',
                                    'billing','client','external_cpa')),
    profile_image_media_id  TEXT,
    is_active               INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    last_login              TEXT,
    created_at              TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at              TEXT, role_set_id TEXT NOT NULL DEFAULT 'role_staff', account_status TEXT NOT NULL DEFAULT 'active' CHECK (account_status IN ('active','pending','deactivated')),
    FOREIGN KEY (individual_id)          REFERENCES individual(id),
    FOREIGN KEY (profile_image_media_id) REFERENCES media_asset(id)
);
