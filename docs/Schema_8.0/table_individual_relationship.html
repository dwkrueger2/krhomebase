individual_relationship

A relationship between two individuals (spouse, parent, child, guardian, ward, sibling, emergency contact) with the relationship named in both directions, a current/former status, and validity dates. Estate-planning workflows use it to model family structure without duplicating people.

Developer notes. One row covers both directions: a_to_b_relationship_lookup_id names how A relates to B, and b_to_a_relationship_lookup_id names how B relates to A. A CHECK prevents relating a person to themselves.

Raw SQL
CREATE TABLE individual_relationship (
    id                                  TEXT PRIMARY KEY,
    individual_a_id                     TEXT NOT NULL,
    individual_b_id                     TEXT NOT NULL,
    a_to_b_relationship_lookup_id       TEXT NOT NULL,
    b_to_a_relationship_lookup_id       TEXT NOT NULL,
    relationship_status                 TEXT NOT NULL DEFAULT 'current'
                                            CHECK (relationship_status IN ('current','former','unknown')),
    valid_from                          TEXT,
    valid_to                            TEXT,
    is_primary                          INTEGER NOT NULL DEFAULT 0 CHECK (is_primary IN (0,1)),
    notes                               TEXT,
    created_at                          TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at                          TEXT,
    CHECK (individual_a_id <> individual_b_id),
    FOREIGN KEY (individual_a_id)               REFERENCES individual(id),
    FOREIGN KEY (individual_b_id)               REFERENCES individual(id),
    FOREIGN KEY (a_to_b_relationship_lookup_id) REFERENCES lookup(id),
    FOREIGN KEY (b_to_a_relationship_lookup_id) REFERENCES lookup(id)
);
