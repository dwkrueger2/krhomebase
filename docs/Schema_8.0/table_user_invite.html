user_invite

Invitation workflow for creating pending users: one-time invite link (stored only as a hash), status, expiry, delivery provider ids, acceptance details, and worker classification (employee, vendor, unspecified).

Domain: Users, Roles, Permissions, Sessions, and Audit

Developer notes. Raw invite tokens are never stored.

Common usage notes
  • Controlled values are enforced by CHECK constraints on: role, status, worker_classification. Update the constraint (table rebuild in SQLite/D1) when adding a value.
  • Sensitive columns: invite_token_hash. Never log them or return them to browsers.
Raw SQL
CREATE TABLE user_invite (
    id                  TEXT PRIMARY KEY,
    email               TEXT NOT NULL,
    role                TEXT NOT NULL CHECK (role IN (
                            'super_admin','attorney','paralegal','staff',
                            'billing','client','external_cpa')),
    invited_user_id     TEXT,
    invited_by_user_id  TEXT,
    invite_token_hash   TEXT NOT NULL UNIQUE,
    status              TEXT NOT NULL DEFAULT 'pending'
                            CHECK (status IN ('pending','accepted','revoked','expired')),
    expires_at          TEXT NOT NULL,
    sent_at             TEXT,
    accepted_at         TEXT,
    accepted_user_id    TEXT,
    email_provider      TEXT,
    email_provider_message_id TEXT,
    resend_message_id   TEXT,
    created_at          TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at          TEXT,
    notes               TEXT, worker_classification TEXT NOT NULL DEFAULT 'employee' CHECK (worker_classification IN ('employee','vendor','unspecified')),
    FOREIGN KEY (invited_user_id)    REFERENCES user(id) ON DELETE SET NULL,
    FOREIGN KEY (invited_by_user_id) REFERENCES user(id) ON DELETE SET NULL,
    FOREIGN KEY (accepted_user_id)   REFERENCES user(id) ON DELETE SET NULL
);
