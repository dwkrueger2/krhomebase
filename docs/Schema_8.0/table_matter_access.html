Table definition · Matter Participation and Access

matter_access

Matter-level access grant used to sandbox users to authorized matters, and to revoke or block access. Includes access level, source of the grant, and revocation details.

Domain: Matter Participation and Access

Developer notes. This is the table the API consults for matter visibility. Revoke by setting revoked_at and is_active = 0 rather than deleting, to keep the audit trail.

Common usage notes
  • Rows are retired rather than deleted: filter on revoked_at (and is_active where present) in normal list views.
  • Controlled values are enforced by CHECK constraints on: access_level, access_source. Update the constraint (table rebuild in SQLite/D1) when adding a value.
Raw SQL
CREATE TABLE matter_access (
    id                   TEXT PRIMARY KEY,
    matter_id            TEXT NOT NULL,
    user_id              TEXT NOT NULL,
    access_level         TEXT NOT NULL DEFAULT 'read_write'
                              CHECK (access_level IN (
                                  'owner','responsible_attorney','assigned_staff',
                                  'billing','read_write','read_only','blocked')),
    access_source        TEXT NOT NULL DEFAULT 'explicit'
                              CHECK (access_source IN ('explicit','matter_assignment','role_default','system')),
    is_active            INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    granted_by_user_id   TEXT,
    granted_at           TEXT NOT NULL DEFAULT (datetime('now')),
    revoked_by_user_id   TEXT,
    revoked_at           TEXT,
    notes                TEXT,
    FOREIGN KEY (matter_id)          REFERENCES matter(id),
    FOREIGN KEY (user_id)            REFERENCES user(id),
    FOREIGN KEY (granted_by_user_id) REFERENCES user(id),
    FOREIGN KEY (revoked_by_user_id) REFERENCES user(id)
);
