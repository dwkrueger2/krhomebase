task_assignee

Assignment of users to a task as assignee or collaborator, with who assigned them, when, and whether the assignment is current. Supports several people per task while task.assigned_to_user_id keeps the primary assignee.

  • Foreign key: task_id → task(id) — ON DELETE CASCADE
  • Foreign key: user_id → user(id) — no ON DELETE action declared (default NO ACTION)
  • Foreign key: assigned_by_user_id → user(id) — no ON DELETE action declared (default NO ACTION)
  • Check: assignment_role must be one of assignee, collaborator.
  • Boolean flags (CHECK IN (0,1)): is_current.

Common usage notes
  • Rows are retired rather than deleted: filter on ended_at (and is_active where present) in normal list views.
  • Controlled values are enforced by CHECK constraints on: assignment_role. Update the constraint (table rebuild in SQLite/D1) when adding a value.
Raw SQL
CREATE TABLE task_assignee (
    id                  TEXT PRIMARY KEY,
    task_id             TEXT NOT NULL,
    user_id             TEXT NOT NULL,
    assignment_role     TEXT NOT NULL DEFAULT 'assignee'
                          CHECK (assignment_role IN ('assignee','collaborator')),
    assigned_by_user_id TEXT,
    assigned_at         TEXT NOT NULL DEFAULT (datetime('now')),
    ended_at            TEXT,
    is_current          INTEGER NOT NULL DEFAULT 1 CHECK (is_current IN (0,1)),
    FOREIGN KEY (task_id)             REFERENCES task(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id)             REFERENCES user(id),
    FOREIGN KEY (assigned_by_user_id) REFERENCES user(id),
    UNIQUE (task_id, user_id, assignment_role, is_current)
);
