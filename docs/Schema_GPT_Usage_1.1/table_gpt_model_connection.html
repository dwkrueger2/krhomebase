gpt_model_connection

One configured way of reaching a model: the connection type (Cloudflare AI Gateway, Gemini, OpenAI, Anthropic Claude, or other), the provider, the exact model identifier, and whether a readiness test has passed. Each row also has a short business-facing connection id.

Group: Gateway configuration
Columns: 17 · Indexes: 2
Outgoing FKs: 0 · Referenced by: 0 tables
Database: krhomebase_gpt_usage_dev (binding GPT_USAGE_DB)
Canonical SQL: Schema_GPT_Usage_1.1.sql
Storage: Cloudflare D1 / SQLite
Developer notes. No credential values live here, only credential_name, which names the credential row to use. The older documentation says one application cannot duplicate the same connection type, provider and model, but the schema has no UNIQUE constraint for that; only kr_gpt_connection_id is unique. application_id has no foreign key.

Raw SQL (as stored in the database)
CREATE TABLE gpt_model_connection (
  id TEXT PRIMARY KEY,
  kr_gpt_connection_id TEXT NOT NULL UNIQUE,
  application_id TEXT NOT NULL,
  connection_type TEXT NOT NULL CHECK (connection_type IN ('cloudflare-ai-gateway','gemini','openai','anthropic-claude','other')),
  provider TEXT NOT NULL,
  llm_model TEXT NOT NULL,
  credential_name TEXT NOT NULL DEFAULT 'api-key',
  config1 TEXT,
  config2 TEXT,
  config3 TEXT,
  state TEXT NOT NULL DEFAULT 'unconfigured' CHECK (state IN ('unconfigured','configured')),
  created_by_user_id TEXT,
  created_by_email TEXT,
  updated_by_user_id TEXT,
  updated_by_email TEXT,
  created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  updated_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  CHECK (length(trim(kr_gpt_connection_id)) > 0),
  CHECK (length(trim(application_id)) > 0),
  CHECK (length(trim(provider)) > 0),
  CHECK (length(trim(llm_model)) > 0),
  CHECK (length(trim(credential_name)) > 0)
);
