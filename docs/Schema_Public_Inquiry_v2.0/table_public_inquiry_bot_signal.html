public_inquiry_bot_signal

One row per inquiry recording the bot-screening evidence: Turnstile result, honeypot result, form timing, and the final decision.

Group: Inquiry intake and review
Columns: 11 · Indexes: 0
Outgoing FKs: 1 · Referenced by: 0 tables
Database: kr_public_inquiry_06_2026 (binding PUBLIC_INQUIRY_DB)
Canonical SQL: schema_public_inquiry_v2_0.sql
Storage: Cloudflare D1 / SQLite
Developer notes. One-to-one with public_inquiry (primary key is inquiry_id). bot_decision has no CHECK list, so the allowed values live only in the Worker code.

Raw SQL (as stored in the database)
CREATE TABLE public_inquiry_bot_signal (
  inquiry_id TEXT PRIMARY KEY,
  submitted_at TEXT NOT NULL,
  turnstile_success INTEGER NOT NULL DEFAULT 0 CHECK (turnstile_success IN (0, 1)),
  turnstile_action TEXT,
  turnstile_hostname TEXT,
  turnstile_error_codes TEXT,
  honeypot_triggered INTEGER NOT NULL DEFAULT 0 CHECK (honeypot_triggered IN (0, 1)),
  bot_decision TEXT NOT NULL,
  form_started_at TEXT,
  form_submitted_at TEXT,
  created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ','now')),
  FOREIGN KEY (inquiry_id) REFERENCES public_inquiry(id) ON DELETE CASCADE
);
