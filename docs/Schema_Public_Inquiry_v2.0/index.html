KR Public Inquiry Database Schema 2.0

A separate, quarantined Cloudflare D1 database that receives untrusted submissions from the public website: consultation requests and site feedback. No unauthenticated request writes to the Homebase operational database. Submissions pass through a signed, encrypted public-inquiry Worker into this database, and a signed-in staff member reviews each one and may promote it into Homebase contacts or matters.

Separate database. This is not part of the Homebase operational database. Database: kr_public_inquiry_06_2026, Worker binding: PUBLIC_INQUIRY_DB. No foreign key crosses into Homebase. Built from the SQL files in the previous repository; the live database was not read.

Cautions
  • Quarantine boundary. This database is deliberately separate from the Homebase operational database. Nothing here is trusted, and no foreign key crosses the boundary. promoted_to_contact_id and promoted_to_matter_id are plain text ids into the Homebase database.
  • Personal data. public_inquiry holds names, email, phone, and a free-text description of a legal problem. metadata and site_feedback hold hashed network identifiers. Apply retention rules and limit access accordingly; expires_at exists for cleanup.
  • Overlapping history tables. public_inquiry_event and public_inquiry_stage_history can both record a status change, and promotion is recorded in public_inquiry_promotion_log and again on public_inquiry. Pick one authoritative source for reports.
  • Free-text status columns. Only public_inquiry.review_status, site_feedback.review_status, party_type, and sync_status have CHECK lists. bot_decision, event_type, previous_status, next_status, urgency, matter_type, and the v2.0 lead fields are unconstrained.
  • Column order differs from logical order. v1.2 (assigned_to, expires_at) and v2.0 (seven lead columns) were added with ALTER TABLE, so those columns sit at the end of public_inquiry in the live table.
  • Built from SQL files, not the live database. This space was built from the unified SQL file in the old repository. The live database was not read. Run the export command in the README to confirm it matches.
